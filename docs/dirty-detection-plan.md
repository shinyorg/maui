# Dirty Detection Source Generator for ViewModels

## Context

Shiny MAUI Shell already guards navigation through `INavigationConfirmation.CanNavigate()`
(`src/Shiny.Maui.Shell/Infrastructure/ShellNavigator.cs:335-360`), but wiring up an
"unsaved changes" prompt today is entirely manual: the developer must hand-track a `hasUnsavedChanges`
flag, implement the interface, and build the dialog by hand (see the README lifecycle example, lines 393-399).

This feature adds a **`[DirtyDetection]` source generator** that:
- Snapshots a ViewModel's public state, detects when it becomes dirty,
- **Validates** the ViewModel (DataAnnotations attributes + a manual hook), and
- Auto-implements `INavigationConfirmation` to prompt Save/Discard before leaving — **blocking the
  save (and the navigation) when validation fails**.

It must be **AOT/trim safe** — no reflection. Property comparison is emitted as explicit
per-property code using `EqualityComparer<T>.Default`; validation is emitted as explicit per-attribute
code (see the Validation section), both mirroring the existing generator's fully-qualified,
reflection-free output style.

The design decisions (confirmed with the user):
1. **2-way dialog** — Save / Discard (uses `IDialogs.Confirm`). Navigation proceeds on either choice
   **unless** Save is chosen and validation fails, in which case navigation is blocked (see #5).
2. **`[SaveDirty]` required, `[CancelDirty]` optional** — enforced at compile time.
3. **Manual `MarkClean()`** captures the baseline (deterministic, async-load safe). Dirty state is
   queryable at three granularities: `IsDirty` (bindable, whole-object), `IsPropertyDirty(x => x.Name)`
   / `IsPropertyDirty("Name")` (single member), and `GetDirtyProperties()` (`string[]` of changed
   members) — all switch/OR dispatch, no reflection.
4. **Overridable `virtual` members.** The generator implements `INavigationConfirmation.CanNavigate()`
   as a `public virtual` method (implicit interface implementation, so it can be overridden), and
   exposes the **confirm-dialog** text through `protected virtual GetDirtyText()` returning a
   `DirtyText` record (Title / Message / SaveText / CancelText only). Consumers override it for
   localization; any `null` member falls back to a default. **`GetDirtyText` owns only the Save/Discard
   dialog chrome — it has nothing to do with validation messages** (see #6).
5. **Validation blocks save silently, errors surface via bindings.** When Save is picked, the
   generated `Validate()` runs (source-generated DataAnnotations checks + the `OnValidate` hook). If it
   produces errors, `CanNavigate()` returns `false` — the user stays, nothing is saved, and **no dialog
   is shown**. Instead `Validate()` refreshes the bindable **`Errors`** / **`IsValid`** properties (with
   `PropertyChanged` notification), so a page bound to them shows the messages inline. Valid → save +
   navigate. Discard always navigates regardless of validity.
6. **Validation messages are owned by the annotations, not by any text record.** A message like
   *"This code requires 3+ characters"* is produced by the attribute itself —
   `[StringLength(8, MinimumLength = 3, ErrorMessage = "This code requires {2}+ characters")]` →
   `GetValidationResult` fills `{0}`=member, `{1}`=max, `{2}`=min. That formatted string lands in
   `ValidationError.Message`. Localization of these messages is done at the attribute (`ErrorMessage`)
   or in `OnValidate` — never in `GetDirtyText`.

## Architecture decisions

- **Extend the existing generator project, add a new generator class.** A Roslyn analyzer
  assembly can host multiple `[Generator]` types. Adding `DirtyDetectionGenerator.cs` to
  `src/Shiny.Maui.Shell.SourceGenerators/` reuses the existing packaging entirely (the DLL is
  already packed to `analyzers/dotnet/cs` from the main library csproj) — no new csproj, no new
  packaging glue, no new test project.
- **Attributes live as normal source in `Shiny.Maui.Shell` (namespace `Shiny`)**, matching how
  `ShellMapAttribute`/`ShellPropertyAttribute` are defined. The generator matches them by
  semantic type name via `CreateSyntaxProvider`, exactly like `GetShellMapClass`.
- **Emit a `partial class`** augmenting the annotated type (unlike the shell generator which emits
  new static classes). Mirror the user's namespace + class name + type-parameter list.
- **Resolve `IDialogs` by scanning the class** for an accessible member of type `Shiny.IDialogs`
  — primary-constructor parameter (read from `ClassDeclarationSyntax.ParameterList`), then field,
  then property — and reference it by name. Primary-constructor parameters are in scope across all
  partial files, so this is legal. Emit **SHINY006** if none is found.

## Property discovery strategy (important)

The repo's ViewModels use CommunityToolkit `[ObservableProperty]` on **fields**, whose public
properties are generated by *another* source generator and are therefore **invisible** to this
generator (generators don't see each other's output). So enumerate BOTH:

1. **Explicitly-declared public get/set properties** (mirror `GetShellProperties` at
   `ShinyShellGenerator.cs:272-331` — require public getter AND setter, skip indexers).
2. **Fields annotated with `[ObservableProperty]`** — snapshot the field directly (its value is
   what mutates; the generated property just wraps it).

Provide a `[DirtyIgnore]` opt-out attribute (on property or field) to exclude UI-state members
(e.g. `SelectedTab`) that shouldn't count as dirty. Skip static members and the generated members
themselves.

## New runtime types — `src/Shiny.Maui.Shell/` (namespace `Shiny`)

- `DirtyDetectionAttribute.cs` — `[AttributeUsage(AttributeTargets.Class)]`, properties
  `string? Title`, `string? Message` (dialog title + body; English defaults if null).
- `SaveDirtyAttribute.cs` — `[AttributeUsage(AttributeTargets.Method)]`, ctor `(string? buttonText = null)`.
- `CancelDirtyAttribute.cs` — `[AttributeUsage(AttributeTargets.Method)]`, ctor `(string? buttonText = null)`.
- `DirtyIgnoreAttribute.cs` — `[AttributeUsage(AttributeTargets.Property | AttributeTargets.Field)]`.
- `DirtyText.cs` — `public sealed record DirtyText(string? Title = null, string? Message = null,
  string? SaveText = null, string? CancelText = null)`. Returned by the overridable `GetDirtyText()`;
  `null` members are defaulted when the dialog is shown.
- `ValidationError.cs` — `public sealed record ValidationError(string? MemberName, string Message)`.
  Returned by the generated `Validate()` and passed to the `OnValidate` hook.

Validation uses **`System.ComponentModel.DataAnnotations` attributes directly** (`[Required]`,
`[Range]`, `[StringLength]`, `[EmailAddress]`, etc.) — no bespoke attribute set. That package is part
of the framework, so no new dependency is introduced.

## Validation (source-generated, AOT-safe)

Two paths, both feeding one `Validate()`:

1. **DataAnnotations attributes** on tracked members (property or `[ObservableProperty]` field). The
   generator finds every attribute whose type derives from
   `System.ComponentModel.DataAnnotations.ValidationAttribute` via the semantic model. Because
   attribute arguments are always compile-time constants, it renders each one as a `new` expression
   from Roslyn `AttributeData` (`ConstructorArguments` + `NamedArguments` as `TypedConstant` literals)
   and emits a `GetValidationResult(...)` call. This is reflection-free over the ViewModel type.
   - **Caveat:** a handful of built-in attributes reflect *inside* their own `IsValid`
     (e.g. `[Compare]`, which looks up another property by name) — those are not fully trim-safe and
     will be documented as such. The common value/format attributes (Required, Range, StringLength,
     Min/MaxLength, EmailAddress, RegularExpression, Phone, Url) are reflection-free.
2. **Manual hook** — `protected virtual void OnValidate(IList<ValidationError> errors)`. Runs after
   the attribute checks; override to add cross-field/custom errors. Empty base implementation.

Validation members are enumerated **independently of dirty tracking** — a `[DirtyIgnore]` member can
still be validated, and a validated member need not be dirty-tracked. `Validate()`, `Errors`,
`IsValid`, and `OnValidate` are always generated (even with zero attributes), so manual-only
validation works.

### Surfacing errors (Option 2 — bindable list)

The generator exposes a bindable error surface rather than `INotifyDataErrorInfo`:

- `public IReadOnlyList<ValidationError> Errors { get; }` — the last computed error set (empty until
  `Validate()` first runs).
- `public bool IsValid { get; }` / `public bool HasErrors { get; }` — derived from `Errors.Count`.
- `public IEnumerable<ValidationError> GetErrors(string? memberName)` — convenience filter for
  binding a single field's error(s) (e.g. via a converter with `ConverterParameter`).
- `public IReadOnlyList<ValidationError> Validate()` — recomputes, **stores** the result in the
  backing field, raises `PropertyChanged` for `Errors`/`IsValid`/`HasErrors`, and returns it.

**Change notification** requires an accessible `OnPropertyChanged(string)` (as provided by
CommunityToolkit `ObservableObject`, the repo's ViewModel base). The generator detects it and calls
it after each `Validate()`; if absent it still emits the properties but they won't notify (documented,
optional info diagnostic). No live-as-you-type wiring is generated — validation is **on-demand**: the
developer calls `Validate()` when needed, and it also runs automatically inside `CanNavigate()` when
Save is picked, which both blocks navigation *and* populates/notifies `Errors` so the page shows them.

## New generator — `src/Shiny.Maui.Shell.SourceGenerators/DirtyDetectionGenerator.cs`

`[Generator(LanguageNames.CSharp)] class DirtyDetectionGenerator : IIncrementalGenerator`.
Pipeline copies the shape of `ShinyShellGenerator.Initialize`:

1. `CreateSyntaxProvider` over `ClassDeclarationSyntax`; keep classes carrying `DirtyDetectionAttribute`.
2. For each, collect: namespace, class name + type params, `partial` modifier presence, the resolved
   `IDialogs` member name, the tracked properties/fields (name + fully-qualified type), the
   `[SaveDirty]` method (name, return-kind sync/Task/ValueTask, button text), the optional
   `[CancelDirty]` method (same), title/message text from `[DirtyDetection]`, and — for each member
   carrying `ValidationAttribute`-derived attributes — the rendered `new`-expression for each
   attribute (from `AttributeData` `TypedConstant` args). These attribute literals are baked into the
   generated base `GetDirtyText()` return value — no override-method detection is needed, since
   localization is done by overriding the emitted `virtual GetDirtyText()`.
3. Optional MSBuild toggle `ShinyMauiShell_GenerateDirtyDetection` (default true) — add a
   `CompilerVisibleProperty` line to `src/Shiny.Maui.Shell.SourceGenerators/build/Package.targets`.
4. `RegisterSourceOutput` emits one `<ClassName>.DirtyDetection.g.cs` per class.

### Generated partial (shape)

```csharp
#nullable enable
namespace <ns>;

partial class <Class> : global::Shiny.INavigationConfirmation
{
    // one snapshot field per tracked member
    private <Type> __dirtySnapshot_<Name>;
    private bool __hasDirtySnapshot;

    public void MarkClean()
    {
        this.__dirtySnapshot_<Name> = this.<Name>;   // repeated per member
        this.__hasDirtySnapshot = true;
    }

    public bool IsDirty
    {
        get
        {
            if (!this.__hasDirtySnapshot) return false;
            return !global::System.Collections.Generic.EqualityComparer<<Type>>.Default
                       .Equals(this.__dirtySnapshot_<Name>, this.<Name>)   // OR-chained per member
                   || ...;
        }
    }

    // Per-property dirty check by name (switch dispatch — no reflection).
    public bool IsPropertyDirty(string propertyName)
    {
        if (!this.__hasDirtySnapshot) return false;
        switch (propertyName)
        {
            case "<Name>":
                return !global::System.Collections.Generic.EqualityComparer<<Type>>.Default
                            .Equals(this.__dirtySnapshot_<Name>, this.<Name>);
            // ... one case per tracked member
            default: return false;
        }
    }

    // Strongly-typed overload — reads the member name off the expression tree (no .Compile()).
    public bool IsPropertyDirty(
        global::System.Linq.Expressions.Expression<global::System.Func<<Class>, object?>> property)
    {
        var __body = property.Body;
        if (__body is global::System.Linq.Expressions.UnaryExpression __u) __body = __u.Operand;  // unwrap boxing Convert
        var __name = (__body as global::System.Linq.Expressions.MemberExpression)?.Member.Name;
        return __name is not null && this.IsPropertyDirty(__name);
    }

    // Names of the members that currently differ from the snapshot.
    public string[] GetDirtyProperties()
    {
        if (!this.__hasDirtySnapshot) return global::System.Array.Empty<string>();
        var __d = new global::System.Collections.Generic.List<string>();
        if (!global::System.Collections.Generic.EqualityComparer<<Type>>.Default
                .Equals(this.__dirtySnapshot_<Name>, this.<Name>)) __d.Add("<Name>");
        // ... one check per tracked member
        return __d.ToArray();
    }

    // ---- validation (Option 2: bindable error list) ----
    private global::System.Collections.Generic.IReadOnlyList<global::Shiny.ValidationError> __validationErrors
        = global::System.Array.Empty<global::Shiny.ValidationError>();

    public global::System.Collections.Generic.IReadOnlyList<global::Shiny.ValidationError> Errors
        => this.__validationErrors;
    public bool IsValid => this.__validationErrors.Count == 0;
    public bool HasErrors => this.__validationErrors.Count > 0;

    public global::System.Collections.Generic.IEnumerable<global::Shiny.ValidationError> GetErrors(string? memberName)
    {
        foreach (var __e in this.__validationErrors)
            if (__e.MemberName == memberName) yield return __e;
    }

    public global::System.Collections.Generic.IReadOnlyList<global::Shiny.ValidationError> Validate()
    {
        var __list = new global::System.Collections.Generic.List<global::Shiny.ValidationError>();

        // per validated member, per DataAnnotations attribute (ctor/named args rendered from AttributeData):
        {
            var __ctx = new global::System.ComponentModel.DataAnnotations.ValidationContext(this)
                { MemberName = "<Member>" };
            var __a = new global::System.ComponentModel.DataAnnotations.RequiredAttribute();
            var __r = __a.GetValidationResult(this.<Member>, __ctx);
            if (__r != global::System.ComponentModel.DataAnnotations.ValidationResult.Success)
                __list.Add(new global::Shiny.ValidationError("<Member>", __r!.ErrorMessage ?? "Invalid"));
        }
        // ... repeated per member/attribute

        this.OnValidate(__list);                 // manual cross-field checks
        this.__validationErrors = __list;
        this.OnPropertyChanged(nameof(this.Errors));    // emitted only if OnPropertyChanged is accessible
        this.OnPropertyChanged(nameof(this.IsValid));
        this.OnPropertyChanged(nameof(this.HasErrors));
        return this.__validationErrors;
    }

    // Manual validation hook — override to add custom errors.
    protected virtual void OnValidate(
        global::System.Collections.Generic.IList<global::Shiny.ValidationError> errors) { }

    // Overridable text hook — base returns the [DirtyDetection]/[SaveDirty]/[CancelDirty]
    // literals (or the built-in defaults where an attribute value was not supplied).
    protected virtual global::Shiny.DirtyText GetDirtyText()
        => new global::Shiny.DirtyText(
            Title: "<attr Title or 'Unsaved Changes'>",
            Message: "<attr Message or 'You have unsaved changes. Save them?'>",
            SaveText: "<[SaveDirty] text or 'Save'>",
            CancelText: "<[CancelDirty] text or 'Discard'>");

    public virtual async global::System.Threading.Tasks.Task<bool> CanNavigate()
    {
        if (!this.IsDirty) return true;

        var __text = this.GetDirtyText();   // may be an override returning null members
        var __save = await this.<dialogsMember>.Confirm(
            __text.Title      ?? "Unsaved Changes",
            __text.Message    ?? "You have unsaved changes. Save them?",
            __text.SaveText   ?? "Save",
            __text.CancelText ?? "Discard");

        if (__save)
        {
            this.Validate();        // refreshes + notifies Errors/IsValid so the page can show them
            if (this.HasErrors)
                return false;       // invalid -> block save + navigation, stay on page (no dialog)

            await <SaveMethod>();   // `await` only if Task/ValueTask, else plain call
            this.MarkClean();
        }
        else
        {
            <CancelMethod>();       // Discard: only emitted if [CancelDirty] present
        }
        return true;               // Discard always leaves; Save leaves only when valid
    }
}
```

Notes:
- Use `EqualityComparer<T>.Default` for every member — AOT-safe, handles value types, strings,
  nullables, and reference types uniformly.
- **`CanNavigate()` is `public virtual`** (implicit interface implementation) so consumers can
  override the whole flow if needed. Explicit interface implementations can't be virtual, hence the
  implicit form.
- **Localization = override the `virtual GetDirtyText()`.** The base implementation bakes in the
  attribute literals (fully populated, never null). A consumer override may return a `DirtyText` with
  any subset of members set; each `null` member is defaulted by the `??` fallbacks in `CanNavigate`.
  This is compiler-checked (`override`), removing the silent-typo risk of the earlier convention-based
  approach.
- After a successful save, call `MarkClean()` so `IsDirty` resets.

### Diagnostics (continue the `SHINY0xx` scheme; existing uses 001-003)

- **SHINY004** (error): `[DirtyDetection]` class is not `partial`.
- **SHINY005** (error): no `[SaveDirty]` method found (Save is required).
- **SHINY006** (error): no accessible `IDialogs` member (ctor param / field / property) found.
- **SHINY007** (error): `[SaveDirty]`/`[CancelDirty]` on an invalid method (must be parameterless;
  return `void`, `Task`, or `ValueTask`), or more than one of either.
- **SHINY008** (warning): `[DirtyDetection]` class has zero trackable members — `IsDirty` is always false.
- **SHINY009** (info, optional): the class has validation attributes but no accessible
  `OnPropertyChanged(string)` — `Errors`/`IsValid` won't raise change notifications, so bindings won't
  update live. Suggests deriving from `ObservableObject`.

(No convention-detection diagnostic is needed — text overriding is a compiler-checked `override` of
the emitted `virtual GetDirtyText()`.)

## Out of scope / noted limitations

- `CanNavigate()` only fires for **user-initiated** navigation (per `ShellNavigator` — programmatic
  `GoBack()` from the Save button won't re-trigger the guard, which is the desired behavior).
- No localization infrastructure exists in the repo; overriding the `virtual GetDirtyText()` (returning
  a `DirtyText` record) is the AOT-safe path for consumers who need localized strings.
- **Validation failure is silent** (no dialog) by design — the app surfaces errors by binding to the
  generated `Errors` / `IsValid` / `HasErrors` (or `GetErrors(member)`), e.g. an error summary, per-field
  labels, or a disabled Save button. We are **not** implementing `INotifyDataErrorInfo`, so there is no
  automatic `{Binding Field}`-level error adornment; and validation is **on-demand** (runs on Save and
  whenever the developer calls `Validate()`), not live-as-you-type unless the developer calls it on change.
- DataAnnotations attributes whose `IsValid` reflects at runtime (notably `[Compare]`, and custom
  attributes that resolve services from the `ValidationContext`) are **not guaranteed trim/AOT-safe**;
  the reflection-free built-ins are the supported set.
